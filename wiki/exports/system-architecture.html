A3불변 원칙 10개와 강제 장치

CLAUDE.md §2. 원칙마다 "누가 막는가"를 붙여 두면 시스템의 신뢰 범위가 보임. 강제 장치가 "규칙 문구"뿐인 항목은 Claude의 준수에 의존

#원칙뜻강제 장치강제 수준
1raw/ 불변원본 스냅샷은 수정 · 삭제하지 않음. 새 스냅샷은 fetch_raw.py로만 생성PreToolUse 훅 guard_raw.py가 Write/Edit를 exit 2로 차단 (raw/inbox/만 예외)훅
2기사 1건 = source 1페이지여러 URL을 묶은 compilation source 금지. source는 raw:와 independent: 보유lint compilation-source(W), unresolved-source(C), source-raw-missing(C)lint
3Grounding Invariant수치 · 시스템명 · 모델명 · 팀 규모 · 날짜는 인용 source의 raw에 verbatim 존재. 없으면 _미공개 (not disclosed)_check_quotes.py(수치 토큰 ↔ raw 텍스트), lint ungrounded-bcd(W, 인용 · 미공개 표기 없는 서술 3건 이상)스크립트
4Hedging 보존소스의 "계획 · 검토 중 · 예정"을 확정형으로 올리지 않음. 벤더 자료는 ⚠️ 벤더 주장:, 도입 기업 발표는 ⚠️ 자사 보고:hr-verifier의 ⚠️ 표기 오류 판정, 스킬 규칙규칙 + 검증
5금지어아마도 · 추정 · 보통 · 일반적으로 · 대개 · 대체로 · 통상 · likely · probably · typically · generally · 추측lint banned-word(W), wikilib.BANNED 목록lint
6부재 확인"페이지가 없다"고 말하기 전에 grep -ril로 확인스킬 절차 (ingest 4단계, research 1단계, compare 1단계)규칙
7숫자는 스크립트가 계산evidence_grade corroborated_by confidence freshness depth는 grade.py, 목차 · 카운트는 build_index.pylint not-graded(C), index-drift(I), grade.py --check스크립트
8자동 수정 금지lint · verify는 보고만. 수정은 사용자 승인 후 한 건씩 (/hr-verify --fix는 사용자가 붙였을 때만)스킬 설계 (lint --fix 폐기)규칙
9기밀클라이언트 · 제안서 유래 페이지는 visibility: internal. 산출물과 외부 모델 전송에서 제외extract_v3 제외 → lint internal-in-export(C) → build_all 게이트 중단 → build_excel 재필터, MCP wiki_read 기본 차단, Aside 작업 투입 금지3중 방어
10log append모든 변경은 wiki/log.md에 ## [YYYY-MM-DD] <op> | ... 추가. op: ingest · lint · verify · research · digest · compare · refactor · manual-edit · review스킬마다 log 포맷 지정. 삭제 · 수정 금지규칙

6근거 사슬 (Grounding Invariant)

Use Case 본문의 숫자 하나가 raw 원문 텍스트까지 이어지는 경로. 끊긴 곳이 있으면 그 수치는 _미공개_로 내려감

① Use Case bullet"⚠️ 벤더 주장: 채용 소요 시간 75% 단축 [[sources/paradox-chipotle-2024-09]]"수치 옆 인용 필수
② sources/ 페이지frontmatter raw: raw/vendors/2026-09-27-paradox-….mdKey Quotes에 같은 문장이 verbatim으로 존재
③ raw 파일원문 텍스트에 "75%"가 글자 그대로 존재snapshot_quality full · partial만 유효. unavailable은 사슬 끊김으로 취급
④ check_quotes.py①의 숫자 토큰을 ③ 텍스트에서 찾음현재 477개 수치 중 미확인 0
무엇을 뽑나퍼센트(75%), 금액($21M, 300억), 큰 수(23,000 · 3,000+ · 1.5M · 5만), 배수(3배, 10x)연월(2025-07 등) · 코드블록 · wikilink 내부는 제외. 만 · 억은 숫자로 환산해 변형 비교
어디서 찾나그 Use Case의 sources: → 각 source의 raw: 텍스트를 합친 집합unavailable · deprecated source 제외. 한 페이지 상세: check_quotes.py <slug>
무엇을 증명하나"그 텍스트가 거기 있다"만. 참 · 거짓과 문맥 일치는 사람 또는 hr-verifier가 판단미확인 비율 50% 초과는 lint warning으로 승격. MCP wiki_verify_quote도 같은 검사
2026-09-27 점검의 결과 126페이지에서 raw에 없던 수치를 _미공개_로 내리고, 2026-10-19 원문 27건 확보 후 raw에 실제로 있는 것만 복원(PwC 65,000명 · $1B, Siemens GBS 8.8점 · 87%, Mercy 50개 병원, IBM AskHR NPS +74). 반대로 raw와 달랐던 ✅ 표기는 정정(BetterUp "성과 16%" → "자신감 16%", DBS 데이터 사이언티스트 250명 → 200명)

7등급 계산 (grade.py)

입력은 Use Case의 sources:와 본문뿐. 대상은 usecases + enterprise-ai. 결과 5개 필드를 frontmatter confidence 뒤에 기록. --dry-run으로 변경 예정만, --check로 불일치 페이지만(exit 2)

STEP 1source 정보 수집source마다 independent(true/false), publisher, unavailable 여부independent 미표기 시 tier 1 · 2 또는 academic · government · analyst · media면 true
STEP 2evidence_graderesolved(존재하고 unavailable 아님) 0건 → D / 서로 다른 publisher의 independent 2+ → A / 1 → B / 0 → Ccorroborated_by = 그 independent 수
STEP 3confidence · freshnesslast_confirmed 경과 개월로 최신성 보정, 미해결 contradiction 1건당 −0.15freshness: D면 unverified, ≤ 12개월 fresh, 초과 stale
STEP 4depthA~E 중 존재하는 섹션 < 2개 또는 실질 섹션 0 → stub / 실질 3+ 이고 Mermaid 1+ → full / 그 외 partial실질 섹션 = B · C · D · E 중 25자 넘는 bullet이 2개 이상이고 미공개 · ❓가 아닌 것
confidence = clamp( base[grade] + recency − 0.15 × unresolved_contradictions , 0.05 , 0.95 ) base : A 0.70 · B 0.45 · C 0.25 · D 0.10 recency : last_confirmed ≤ 6개월 +0.10 · ≤ 12개월 0 · ≤ 24개월 −0.10 · > 24개월 −0.20 freshness : grade D → unverified · ≤ 12개월 → fresh · 초과 → stale
A독립 소스 2개 이상제안서 reference case로 인용
B독립 소스 1개조건 명시하고 인용
C벤더 · 자사 보고만"벤더 주장"으로만 인용
D소스 없음 · 전부 unavailable인용 금지

제안서 인용 기준 = A · B and depth full (Bases "제안서 인용 가능" 뷰). confidence는 필터용 파생값일 뿐 등급을 대체하지 않음. sources.md 상단의 tier 가중치 합산 공식은 2026-09-27 폐기(문서에는 이력으로 남아 있음)

fetch_raw.py가 저장한 원문 텍스트 파일. 불변. 모든 수치의 최종 근거
source
기사 1건에 대응하는 wiki 페이지. raw를 가리키고 Key Quotes를 verbatim으로 보관
Use Case
HR 프로세스에 AI를 적용한 사례 1건. adoption(도입 기업) 또는 vendor-product
enterprise-ai
전사 GenAI 플랫폼 사례. HR 프로세스 변화가 소스에 없으면 여기. 카운트 제외
reference
법령 · 리포트 · 제도 맥락 페이지. 산출물 제외
evidence_grade
A 독립 2+ · B 독립 1 · C 벤더 · 자사만 · D 없음. grade.py 계산
corroborated_by
서로 다른 publisher의 독립 소스 수
depth
full · partial · stub. B~E 실질 bullet과 Mermaid 유무로 계산
freshness
fresh(12개월 이내) · stale · unverified(D)
confidence
등급 기반 파생 숫자. 필터용, 등급을 대체하지 않음
Grounding Invariant
본문 수치가 인용 source의 raw에 verbatim 존재해야 한다는 불변 조건
Hedging 보존
소스의 계획 · 검토 중 · 예정 표현을 확정형으로 올리지 않는 규칙
compilation source
여러 URL을 묶은 source. 2026-09 이후 금지, 기존 4개는 deprecated
contradiction
두 소스의 값 충돌. unresolved(보류) 또는 superseded(우세한 값으로 재작성)
Triage
ingest 1단계 판정: New · Update · Disputed · No material
Tier vs independent
Tier는 발화자 종류(1~4), independent는 이해관계 유무. 등급은 independent만 봄
snapshot_quality
full · partial · failed(raw) / llm-extracted · unavailable(source)
fetched_via
direct · jina · aside · aside-repl · wayback. 어느 경로로 원문을 받았는지
visibility
public · internal. internal은 산출물 · MCP 기본 읽기 · 외부 모델 전송 제외
regulatory_exposure
kr-high-impact · kr-high-impact-review · eu-annex-iii
Dataview · Bases
Obsidian에서 frontmatter를 표로 자동 집계하는 플러그인과 내장 기능
hook
Claude Code가 도구 실행 전후에 자동 실행하는 명령. 여기서는 raw 차단과 lint
skill
/hr-… 슬래시 명령. SKILL.md에 절차 · 금지 · 산출이 고정
subagent
별도 컨텍스트로 도는 보조 에이전트. hr-verifier 1개, 쓰기 금지
MCP
Model Context Protocol. hr-wiki(읽기 전용 wiki 도구)와 aside(브라우저) 서버
Aside repl · exec · Routine
repl은 JS로 탭을 열어 텍스트 추출(결정론), exec는 에이전트 모드(승인 필요), Routine은 Aside 내장 예약 작업
Jina Reader
r.jina.ai 뒤에 URL을 붙여 본문 텍스트를 받는 서비스. 폴백 2단계
Wayback id_
archive.org 사본을 원본 그대로 받는 URL 형식. 폴백 4단계
golden Q&A
evals/golden-qa.json 30문항. wiki만 보고 답해야 하는 회귀 평가 세트
명사형 종결
wiki 본문 문체 규칙(style-guide.md). 문장을 명사로 끝내고 엠대시 · 홍보 표현 금지. Key Quotes · log · 코드는 제외
