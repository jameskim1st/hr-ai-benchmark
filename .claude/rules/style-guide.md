# 문체 가이드: 명사형 종결(개조식) — use case · source · synthesis 본문에 적용

사내 보고서, 운영안, 회의 자료처럼 **읽는 사람이 빠르게 훑어보는 문서**에 쓰는 문체. 2026-10-19 사용자 지정. wiki 산출물(use case 본문·표·도식 문구, source 요약, synthesis, Consulting Angle)에 적용. 코드, 원문 인용(Key Quotes·blockquote), 고유명사, 책·강좌 제목은 원문 그대로. 회의록·대화 응답에는 적용하지 않음.

## 1. 종결: 단어로 끝냄
- 문장의 끝은 명사(또는 명사처럼 쓰이는 말)로 끝낸다. 예: 운영, 확정, 제출, 검토, 진행, 필요, 가능, 예정, 여부, 우려, 제안
- 서술형 종결("~합니다", "~입니다", "~한다")을 쓰지 않는다.
- 명사형 어미 "-함", "-임", "-음", "-됨"으로도 끝내지 않는다. 단어 자체로 끝낸다.
  · "검토함" → "검토"   · "필요함" → "필요"   · "가능함" → "가능"
- 끝에만 명사를 쓰고, 문장 안쪽의 조사와 어미는 생략하지 않는다. 의미 관계가 흐려지지 않는 것이 우선.
  · 나쁨: "지출 비용 추론 용도 토큰 카운트 함수 오류 시 대응"
  · 좋음: "지출한 비용을 추론하는 토큰 카운트 함수에 오류가 생기면 즉시 대응"

## 2. 한 칸 · 한 줄에 여러 내용이 있을 때
- 내용 사이는 마침표와 공백(". ")으로 나눈다. 마지막 내용 끝에는 마침표를 찍지 않는다.
  예: "필수 트랙 1개와 선택 모듈 1개만 동시 운영. 심화 과정은 추후 검토"
- 한 항목에는 한 가지 결론만 담는다. 길어지면 항목을 나눈다.

## 3. 판단 · 상태를 나타내는 끝말
- 제안: "~ 제안", "채택 제안"
- 필요: "~ 필요", "~ 확인 필요", "~ 검토 필요"
- 가능 · 예정: "~ 가능", "~ 예정"
- 우려: "~ 우려"
- 미결정: "~ 여부", "미정"
- 확정된 사항과 논의 중인 사항을 끝말로 구분한다. ("확정" vs "검토 필요" · "미정")
- wiki 표기와의 결합: 근거 표기 접두사(✅ Fact · ⚠️ 벤더 주장 · ⚠️ 자사 보고 · `_미공개 (not disclosed)_`)는 그대로 두고, 그 뒤 서술만 명사형으로 끝낸다. 예: "⚠️ 벤더 주장: 채용 소요 시간 75% 단축 (독립 검증 없음)"

## 4. 나열과 기호
- 단어 둘은 "와/과", 셋 이상은 쉼표로 나열한다.
- 가운뎃점(" · ")은 짧은 명사 묶음(예: 직무 · 역량 체계)에만 쓴다. 문장을 압축하는 용도로 쓰지 않는다.
- 화살표(→)는 순서 · 결과 · 이동에만 쓴다. (예: 녹취 → 지식 파일 → 빌더)
- 엠대시(—)는 쓰지 않는다. 콜론이나 쉼표로 바꾼다.
- 날짜는 "10/12", "11/16 주", "2026-10-09"처럼 쓴다. (frontmatter와 log는 기존 규칙대로 `YYYY-MM-DD`)

## 5. 어휘
- 비유어 대신 일반 어휘를 쓴다. ("뼈대" → "기본 틀", "흡수" → "대응", "얇게" → "간략히")
- 홍보 · 마케팅 표현을 쓰지 않는다. (슬로건, 감탄, "혁신적인", "획기적인", 과장된 수식어)
- 업무 외래어는 정착된 표기를 쓰고, 없으면 원어를 쓴다. (Tool, Skill, Align)
- 다음 용어는 영문으로 쓴다: Use Case(유스케이스 X), Asset(에셋 X), Workforce(워크포스 X)
- HR 업무 영역은 "채용, 보상 등 모듈"처럼 HR 모듈 단위로 부른다.

## 6. 제목 · 라벨
- 제목, 표 머리글, 짧은 라벨은 명사구로 쓴다. (예: "운영 원칙", "참여자 부담")

## 7. 작성 후 점검
- [ ] 모든 문장이 단어로 끝나는가 ("~합니다", "-함", "-임"이 남지 않았는가)
- [ ] 문장 안쪽의 조사가 빠져 의미가 흐려진 곳은 없는가
- [ ] 한 칸에 여러 내용이 있으면 ". "으로 나눴고, 마지막에 마침표가 없는가
- [ ] 확정 · 제안 · 검토 필요 · 미정이 끝말로 구분되는가
- [ ] 엠대시, 비유어, 홍보성 표현, 직급 호칭이 없는가

|---|---|

| 11/16 주에 킥오프를 하고, 1/18 주에 필수 1기 데모데이를 엽니다. | 11/16 주 킥오프, 1/18 주 필수 1기 데모데이 |
| 채택을 제안합니다. | 채택 제안 |
| 참여자 대부분이 고객사에 상주하므로, 참석하지 못하는 인원이 늘어날 우려가 있습니다. | 참여자 대부분이 고객사에 상주하므로 불참 인원 증가 우려 |
| 세션은 회당 60분을 넘기지 않습니다. | 세션은 회당 60분 이내 |
| 과제 8회 중 6회 이상을 제출하고 데모데이에서 발표하면 수료로 인정합니다. | 과제 8회 중 6회 이상 제출과 데모데이 발표 시 수료 인정 |
| 팀이나 회사에 도서비 지원을 요청할지 검토해야 합니다. | 팀이나 회사에 도서비 지원 요청 여부 검토 필요 |
| 2회 연속으로 불참하고 기여한 내용도 없으면 옵저버로 전환합니다. | 2회 연속 불참하고 기여도 없으면 옵저버로 전환 |
