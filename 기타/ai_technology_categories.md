# AI 기술 유형 정리

> **목적**: 과제정의서의 ③ AI 기술 유형 항목을 작성할 때 카테고리별 정의·구분 기준·실수하기 쉬운 포인트를 정리.
> **사용법**: Agent가 하는 작업을 어느 카테고리에 매핑할지 헷갈릴 때 이 문서를 펼쳐서 정의를 확인.

---

## 카테고리 전체 구조

PwC 양식의 5개 대분류 + 세부 항목:

```
① 생성형 (Generative)
   - 텍스트 생성
   - 요약·재작성·질의응답
   - 멀티모달 생성·이해
   - 정보 추출

② 판별·예측 (Predictive)
   - 예측
   - 군집·분류
   - 추천·랭킹

③ 인식 (Recognition)
   - OCR
   - 음성 인식

④ 의사결정·최적화 (Decision·Optimization)
   - 최적화

⑤ 자동화 (Automation)
   - RPA
```

---

## ① 생성형 (Generative)

데이터로부터 **새로운 콘텐츠를 만들어내는** AI. 주로 LLM(대규모 언어 모델)·생성 모델 기반.

### 텍스트 생성

**정의**: 주어진 프롬프트나 맥락으로부터 **자유로운 텍스트를 새로 생성**하는 작업. zero-shot 또는 few-shot 생성에 가까움.

**해당 예시**
- 창작 글 작성 (에세이·시·소설)
- 아이디어 생성·브레인스토밍
- 자유 형식 답변 생성 (주어진 Template 없이)

**해당하지 않는 예시 (실수 주의)**
- ❌ Template + 변수 치환 + tone 조정 방식의 메일 작성 → "요약·재작성·질의응답"
- ❌ 기존 데이터를 받아 형태만 바꾸는 작업

### 요약·재작성·질의응답 ⭐ (한국 업무 자동화 메일·문서 작성 대부분이 이쪽)

**정의**: 주어진 정보를 받아 **형태·톤·길이를 바꾸는** 작업. 새로 만들기보다 기존 정보의 재가공이 중심.

**해당 예시**
- LMS 정보를 매핑해 답변 메일 본문 재작성 (정중한 tone)
- 직급·사유에 맞는 Template variant 선택 + 변수 치환 → 사유서 메일 본문 작성
- 추출된 규정 문구 + 개인 정보 → 맞춤 안내 메일 재작성
- 긴 문서를 한 줄 요약
- 주어진 자료에 기반한 Q&A 답변

**판단 기준**: "주어진 정보가 있는가?" → **있다면 거의 항상 이쪽**. 비즈니스 자동화의 메일·보고서·안내문 작성은 대부분 여기.

### 멀티모달 생성·이해

**정의**: 텍스트 + 이미지/오디오/영상 등 **여러 modality를 함께 다루는** 작업.

**해당 예시**
- 이미지를 보고 설명 생성 (image captioning)
- 텍스트 프롬프트로 이미지 생성
- 차트/표를 보고 자연어로 설명
- 도면·다이어그램 분석

**해당하지 않는 예시**
- ❌ PDF에서 텍스트만 뽑아내는 작업 → "정보 추출" (멀티모달이 아님)

### 정보 추출

**정의**: 비정형 텍스트(메일·문서·PDF)에서 **구조화된 필드를 뽑아내는** 작업. 주로 NER, 정규표현식·LLM 기반 추출.

**해당 예시**
- 메일 본문에서 과정명·차수·취소사유 추출
- 교육 안내 메일에서 교육명·일자·장소·대상자 추출
- HR 명부·PPT 규정에서 지역 조건·한도·신청 절차 문구 추출
- 계약서에서 계약일·금액·당사자 추출

**해당하지 않는 예시 (실수 주의)**
- ❌ 추출된 값을 다른 데이터와 매칭해 분류하는 작업 → 추출은 추출, 분류는 "군집·분류"로 분리

## ② 판별·예측 (Predictive)

데이터를 입력받아 **클래스 또는 값으로 출력**하는 AI. 주로 ML 모델·규칙 엔진·LLM 분류기.

### 예측 (Prediction) ⚠️ (가장 자주 잘못 체크하는 항목)

**정의**: 데이터로부터 학습된 모델이 **확률적으로 미래 값/사건을 추론**. 핵심은 **불확실성을 다루는 것**.

**해당 예시**
- 매출 예측 (다음 분기 매출액)
- 고객 이탈 예측 (해약 확률)
- 수요 예측 (재고 필요량)
- 고장 예측 (장비 고장 시점)
- 신용 위험 예측

**판단 기준**:
1. 미래의 값/사건을 추론하는가?
2. 출력에 **확률·불확실성**이 본질적으로 들어가는가?
3. 학습 데이터로부터 통계적 패턴을 학습한 모델이 필요한가?

위 세 가지가 모두 yes일 때만 "예측".

**해당하지 않는 예시 (실수 주의)** ⚠️
- ❌ 인입시간 vs. deadline 비교 → 페널티 부과 여부 결정 → **"군집·분류"** (확률적 추론 아님, 결정론적 규칙 매칭)
- ❌ 근무지 vs. 교육 장소 매칭 → 출장비 지원 여부 결정 → **"군집·분류"** (이미 있는 규칙에 입력 대입)
- ❌ binary yes/no 결정이라고 다 예측이 아님. 결정 방식이 **규칙 기반**이면 분류, **학습된 모델 기반의 확률적 추론**이면 예측.

### 군집·분류 ⭐ (규칙 기반 판정도 여기)

**정의**: 입력을 정해진 **클래스로 나누는** 작업. ML 분류기·LLM 분류기·규칙 기반 판정 모두 포함.

**해당 예시**
- 메일을 취소/변경/기타 카테고리로 분류
- 페널티 부과 vs 면제 분류 (규칙 기반: deadline 비교 + 예외사유 매칭)
- 출장비 지원 vs 불가 분류 (규칙 기반: 근무지 vs 교육 장소 매칭)
- 문서를 주제별로 군집화
- 스팸/정상 메일 분류

**판단 기준**: "입력을 미리 정의된 N개 클래스 중 하나로 떨어뜨리는가?"

**규칙 기반 판정도 분류로 본다** ⚠️
- LLM이 분류기로 동작하든, 단순 if-else 규칙이든, ML 모델이든 — **출력이 카테고리(클래스)면 분류**.
- 이게 "예측"과의 가장 흔한 혼동 지점이므로 명확히 구분해야 함.

### 추천·랭킹

**정의**: 후보들 중 **가장 적절한 것을 골라 순위를 매기는** 작업.

**해당 예시**
- 상품 추천 (사용자 선호 기반)
- 검색 결과 랭킹
- 인재 매칭 (적합도 순위)
- 콘텐츠 추천 (영화·뉴스 등)

**해당하지 않는 예시**
- ❌ 단순 매칭/대조 (예: 근무지 ↔ 교육 장소) → "군집·분류"
- ❌ 두 값 비교만 하는 작업 → 추천이 아님

## ③ 인식 (Recognition)

**비정형 입력(이미지·음성)에서 텍스트나 의미를 뽑아내는** 작업.

### OCR (Optical Character Recognition)

**정의**: 이미지·스캔본·PDF에서 **문자 영역을 인식해 텍스트로 변환**.

**해당 예시**
- 종이 문서 스캔 → 텍스트 디지털화
- 이미지 PDF에서 텍스트 추출
- 영수증·신분증·서류 OCR

**해당하지 않는 예시**
- ❌ 텍스트가 이미 들어 있는 PDF에서 텍스트 뽑기 → OCR 없이 가능, 단순 정보 추출

### 음성 인식 (Speech Recognition / STT)

**정의**: 음성 파일이나 실시간 음성을 **텍스트로 변환**.

**해당 예시**
- 회의록 자동 작성 (음성 → 텍스트)
- 콜센터 통화 transcript
- 음성 명령 인식

---

## ④ 의사결정·최적화 (Decision·Optimization)

**여러 대안 중 최적해를 찾는** 작업.

### 최적화 ⚠️ (실수 주의 — 단순 판정은 최적화가 아님)

**정의**: 제약 조건 하에서 목적함수를 **최대화/최소화**하는 해를 탐색. 선형계획법·유전알고리즘·강화학습·시뮬레이티드 어닐링 등.

**해당 예시**
- 배송 경로 최적화 (TSP)
- 인력 배치 최적화 (제약 조건: 시간·자격·인건비)
- 생산 일정 최적화
- 포트폴리오 최적화
- 자원 할당 최적화

**판단 기준**:
1. 여러 가능한 해(solutions) 중에서 고르는가?
2. 목적함수와 제약 조건이 명시적으로 정의되는가?
3. 최적화 알고리즘(선형계획법·휴리스틱·메타휴리스틱 등)이 들어갈 자리가 있는가?

위 세 가지가 모두 yes일 때만 "최적화".

**해당하지 않는 예시 (실수 주의)** ⚠️
- ❌ 단순 binary 판정(부과/면제, 지원/불가) → "군집·분류"
- ❌ 규칙 기반 매칭 (근무지 vs 교육 장소) → "군집·분류"
- ❌ "최적의 메일 톤 선택" 같은 표현은 사실 Template variant 분류 → "요약·재작성"
- ❌ 알고리즘적 의미의 optimization이 들어갈 자리가 없으면 체크하지 않는다

---

## ⑤ 자동화 (Automation)

**시스템·UI를 자동으로 조작하는** 작업.

### RPA (Robotic Process Automation)

**정의**: 화면·키보드·클릭·시스템 API를 자동화해 **사람이 하던 단순 반복 작업을 봇이 대신 수행**.

**해당 예시**
- ERP 시스템에 데이터 자동 입력
- Excel 파일 자동 다운로드 → 양식 변환 → 업로드
- 여러 시스템 간 데이터 복사·붙여넣기
- 화면 클릭·스크린 자동화

**해당하지 않는 예시**
- ❌ AI 모델이 메일을 자동으로 분류·작성 → AI 자동화이지 RPA는 아님
- ❌ API 호출만으로 처리되는 자동화는 일반적으로 RPA로 분류 안 함

## 실전 매핑 가이드 — 자주 보는 작업의 분류

| 작업 | 카테고리 매핑 |
|---|---|
| 메일 본문에서 과정명·차수·사유 등 필드 추출 | ① 정보 추출 |
| Template + 변수 치환으로 메일 작성 | ① 요약·재작성·질의응답 |
| 직급/사유별 톤으로 메일 본문 재작성 | ① 요약·재작성·질의응답 |
| 메일 카테고리 분류 (취소/변경/기타) | ② 군집·분류 |
| 규칙 기반 판정 (deadline 비교, 규정 매칭) | ② 군집·분류 |
| 매출·이탈·수요 예측 | ② 예측 |
| 후보 중 적합도 순위 매기기 | ② 추천·랭킹 |
| 종이 문서 → 텍스트 변환 | ③ OCR |
| 회의 음성 → 텍스트 | ③ 음성 인식 |
| 배송 경로·인력 배치 최적화 | ④ 최적화 |
| ERP 자동 입력·파일 자동 처리 | ⑤ RPA |

## 헷갈릴 때 자기점검 질문

1. **"새로 만드는가, 기존 정보를 변형하는가?"** → 새로 만들기는 텍스트 생성, 변형은 요약·재작성
2. **"미래의 확률적 추론인가, 현재의 규칙 매칭인가?"** → 미래 추론은 예측, 규칙 매칭은 군집·분류
3. **"최적화 알고리즘이 들어갈 자리가 있는가?"** → 없으면 최적화 체크 안 함
4. **"입력이 비정형(이미지·음성)인가?"** → yes면 인식 카테고리 (OCR/음성)
5. **"화면·시스템을 봇이 자동 조작하는가?"** → yes면 RPA, AI 처리만이면 아님
